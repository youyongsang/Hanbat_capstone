2026-08-28 진단: sta_tx_bitrate feature 시도 → 실패

가설: iw station dump의 station별 tx bitrate(PHY rate)가 rate control
후퇴를 잡아내 occ 55~75%의 label 2 vs 3을 가를 것.

diag_25 런 (146행, 8-feature 스키마):
  sta_tx_bitrate_min : L1/L2/L3 전부 median 6.5 (범위 6~6) — 상수.
    트래픽 없는 유휴 station(-30dBm, MCS 0)이 min을 매 행 지배.
  sta_tx_bitrate_mean: L1 24 / L2 33 / L3 35 — throughput을 그대로 추종.
    occ 55~75%만: L2 mean 29 (thr 78) vs L3 mean 51 (thr 97) — L3가 오히려
    높음 (폰이 세게 밀어 rate 높음). victim 건강과 반대.
  그 구간 L3는 latency 0 + probe loss 14% = failure=max. 채널 쪽 지문 없음.

결론: 채널 텔레메트리로 못 잡는 잔차는 in-band victim 프로브 없이 원리상
탐지 불가. 6-feature 모델(test 85.5% / L3 recall 76% / F1 0.81)이 최종.
sta_tx_bitrate_*는 CSV엔 계속 기록(정보용), 모델 입력엔 미사용.

2026-08-28 Option 1: forecasting (label k polls ahead) 평가
================================================================
scratchpad/forecast_eval.py — relabeled CSV로 윈도우 target을 k폴링 뒤
라벨로 두고 재학습. 폴링 ~1~2s이므로 k=3은 ~3~6s, k=5는 ~5~10s 앞.

                  overall acc   severe R / P / F1
k=0  LSTM             84.6%       75.0 / 65.2 / 69.8
     occ rule@t       88.9%       50.0 / 100  / 66.7
     persistence      100%        (target=현재라벨이라 자명)

k=3  LSTM             69.6%       80.0 / 43.2 / 56.1
     occ rule@t       78.7%       52.5 / 72.4 / 60.9
     persistence      80.0%       70.0 / 66.7 / 68.3
     ESCALATION (label<3 now -> 3 in k=3), 12창:
        LSTM      8/12 = 67%
        occ rule  0/12 = 0%   (persistence도 정의상 0)

k=5  LSTM             73.6%       65.0 / 57.8 / 61.2
     occ rule@t       71.8%       40.0 / 64.0 / 49.2
     persistence      73.6%       65.0 / 60.5 / 62.7
     ESCALATION, 14창:  LSTM 5/14 = 36%,  occ rule 0/14

해석:
- LSTM은 전체 정확도로는 persistence("5초 뒤에도 똑같을 것")를 못 이긴다.
  단기 예측에서 persistence는 강한 baseline.
- LSTM의 고유 가치 = "심각으로의 상승(escalation) 조기경보". 지금 심각이
  아닌데 3초 뒤 심각이 되는 창을 LSTM은 67% 잡고, 반응형 occupancy 문턱과
  persistence는 0% (원리상). occ 상승 + retry 상승 + RSSI 불안정화 추세로
  선 넘기 전에 감지.
- 대가: precision 하락(43%) — 조기경보를 위해 오탐을 감수. lead-time/recall
  트레이드오프. band steering처럼 "QoS 완전 붕괴 전에 조치"하려는
  mitigation 시스템에 유용.
- 유용 지평선은 짧음 (~3~6s). k=5에선 신호 약해짐(36%). escalation 표본이
  작아(12~14창) 수치는 노이즈 — 데이터 더 쌓으면 firm up.

결론: LSTM을 "더 나은 분류기"가 아니라 "심각 전이 3~6초 조기경보기"로
포지셔닝. 이게 LSTM(시계열)을 문턱·feedforward 대신 쓰는 이유.
