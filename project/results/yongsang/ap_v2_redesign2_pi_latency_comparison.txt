AP redesign2 Raspberry Pi 실측 지연 비교 (2026-08-29 갱신 2차 — sta_tx_bitrate_mean 7-feature 승격)


배경: item 2(sta_tx_bitrate_mean escalation 지문 재검토) 다중 시드 검증(5시드 x 4개 설정)에서
7-feature가 exit-loss 가중치와 무관하게 항상 6-feature를 이김을 확인(Label3 F1 +5~11pt).
`ap_features.py`에 sta_tx_bitrate_mean을 7번째 입력으로 승격 -> Baseline/SDN-style/Proposed
세 모델 전부 7-feature로 재변환·재학습(각 3시드, val balanced acc 최고 배포) -> ONNX 재수출 ->
Pi 재측정까지 전체 파이프라인 갱신.

같은 세션에서 item 1(EE exit-loss 가중치를 SDN 스타일로)의 승격도 재검토됨: 다중 시드로 보니
SDN 가중치가 균등 가중치보다 낫다는 근거가 없었고(오히려 근소 열세), SDNLSTM은 EarlyExitLSTM과
백본이 의도적으로 동일해서 같은 가중치를 쓰면 두 모델이 사실상 같은 네트워크가 되어 비교 자체가
무의미해짐 -> Proposed는 균등 가중치(0.3/0.3/0.4)로 되돌림. 6-feature 시절 체크포인트/ONNX/결과는
`*_6feat_archived_20260829.*` 및 `checkpoints/ap_v2_redesign2_6feat_archived_20260829/`,
`data/ap_metrics_v2_redesign2_6feat_archived_20260829/`, Pi `~/ap_pi_v2/archived_6feat_20260829/`에
전부 보존.

학습 파이프라인에 `--seed` 옵션 신규 추가(`train_ap_early_exit.py`/`train_ap_sdn.py`/
`train_ap_baseline_lstm.py`) — 그 전까지 시드 고정이 전혀 없어 단일 실행 A/B 비교가
신뢰할 수 없었음(같은 6-feature+SDN 가중치 설정을 시드만 바꿔 재실행하면 test 정확도가
91.3%->80.0%, Label3 F1이 66.7%->51.1%로 요동침). 이번 배포는 각 아키텍처마다 시드 0/1/2로
학습 후 val balanced acc 최고를 선택.

Pi: capstone@192.168.8.109, onnxruntime CPU, 같은 세션에서 4개 모델 전부 재측정(5회 반복/샘플 평균).
