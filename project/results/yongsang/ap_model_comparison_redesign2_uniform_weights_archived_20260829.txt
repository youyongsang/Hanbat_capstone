2026-08-28 (같은 세션, 후속): "왜 SDN이 이겼나" 재조사 — threshold 문제 아님, recall/precision 트레이드오프
================================================================

**1) confidence/entropy threshold sweep (val set으로 튜닝, test로 확인)**:
둘 다 배포된 값이 이미 val 기준 최적점 근처였다 — 튜닝 부족이 원인이 아니다.

  SDN confidence T sweep (val):  T=0.80~0.99 전부 val_balanced 86.2%로 동일(plateau).
    배포값 T=0.85가 이미 이 plateau 안에 있음.
  EE  entropy theta sweep (val): theta=(0.15~0.4, 0.3~0.7) 전부 val_balanced 85.4%로 동일(plateau).
    배포값 (0.3,0.6)이 이미 이 plateau 안에 있음.
  → test 표본(31개, 소표본)에서는 그 안 어느 값을 골라도 test 결과가 변하지 않음(둘 다 동일 값 재현).

**2) test set 전체 재평가 — recall만 볼 게 아니라 precision/F1까지 봐야 함**:

  방법                recall   precision    F1
  SDN (T=0.85)         64.5%      46.5%    54.1%
  EE  (theta=0.3/0.6)  51.6%      66.7%    58.2%   <- F1은 오히려 EE가 근소 우위

  **SDN은 recall을 더 챙기는 대신 precision을 크게 희생한다**(혼잡을 심각으로
  과잉탐지 — FP가 많음). "SDN이 이겼다"는 이전 결론은 recall 숫자 하나만 보고
  낸 성급한 결론이었다. F1(recall·precision 조화평균)로 보면 두 모델은
  막상막하이고, 오히려 EE가 근소하게 앞선다.

**3) true label-3(31창)이 어느 exit에서 잡혔는지 분해**:

  SDN: exit1 2개(2/2 정답) / exit2 13개(11/13 정답) / exit3 16개(7/16 정답)
  EE : exit2 10개(10/10 정답, 전부 맞음) / exit3 21개(6/21 정답)

  EE는 심각 창을 더 많이 exit3까지 끌고 가는데(21개 vs SDN 16개), exit3의
  심각 탐지력이 낮다(6/21=29%) — exit2에서 잡을 수 있었으면 100% 맞히는데
  (10/10) 정작 exit3로 넘어가는 비중이 SDN보다 크다. SDN의 loss 가중치
  (0.15/0.30/0.55, 뒤쪽 exit에 더 강하게)가 exit3 학습을 EE의 균등 가중치
  (0.3/0.3/0.4)보다 심각 클래스에 유리하게 만들었을 가능성이 있다 — 다음에
  EE의 exit별 loss 가중치를 SDN 스타일로 바꿔서 재학습해보는 것도 검토할
  만하다(현재는 미실행, 후속 과제로 남김).

**정정된 최종 결론**: 속도는 SDN이 확실히 앞선다(0.600ms vs 0.641ms, 세션
호출 구조는 동일하니 architecture 자체의 계산량/threshold plateau 차이).
정확도 지표는 recall만 보면 SDN이 앞서 보이지만 precision까지 고려한 F1은
막상막하(오히려 EE가 근소 우위) — "SDN이 전면적으로 더 낫다"는 표현은
부정확하고, "SDN은 recall-precision 트레이드오프를 다르게 잡았고 속도가
더 빠르다"가 정확한 요약이다.
