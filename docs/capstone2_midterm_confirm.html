왜 max로 조합했나보강

왜
슬라이드 8에 "가중치 논쟁 없음"만 있음. "왜 평균이 아니고 max?" 예상 질문
슬라이드 8 보강 또는 Q&A 답변
  • 표준은 조합법을 안 준다 — ITU-T·Cisco는 "각 축이 언제 나쁜가"(문턱)는 규정하지만 "어떻게 합치나"(가중치)는 규정 안 함. weighted-sum은 가중치(occ 0.45 등)를 임의로 정해야 했고, 그게 1차 순환논리의 원인
  • QoS는 병목이 지배 — jitter가 완벽해도 loss 10%면 VoIP는 못 씀. 평균 내면 그 사실이 희석됨. 가장 나쁜 축이 사용자 체감을 결정
  • 정의가 명확 — label 3 = 최소 한 축이 표준 심각 문턱 초과 (occ≥75% OR jitter≥50ms OR loss≥5% OR 편도≥150ms)
  • 정석은 ITU-T G.107 E-model이나 계산이 무거워 max로 단순화 (슬라이드 17 [3]에 이미 명시)
유용상

왜 지속성 게이트를 k=2 / m=2로 했나보강

왜
슬라이드 8에 "6조합×5시드 스윕으로 최적값 선택"만. 왜 2/2가 최적인지 없음
슬라이드 8 보강 또는 부록 슬라이드

게이트가 필요한 이유: ping 1회 타임아웃, 1폴링 loss 스파이크만으로도 Label 3(심각)이 붙어서, 실제 QoS 붕괴가 아닌 지터성 잡음이 심각 라벨에 섞였다. → 규칙: 비-점유율 축(jitter/loss/latency)이 심각(≥0.75)이어도 최근 k폴링 중 m폴링 이상 유지될 때만 Label 3 확정, 아니면 혼잡(2)으로 강등.

어떻게 골랐나: 6개 조합 nogate · k2m2 · k3m2 · k3m3 · k5m2 · k5m3 × 5시드 스윕 (2026-09-02, 18차).

k=2 / m=2가 최적인 이유:

  • 강등된 행 35개 → nogate 대비 거의 최소 = 라벨을 가장 적게 건드림
  • 그런데 Label 3 recall·F1은 6개 조합 중 최고
  • k를 키우면(3, 5) 더 많은 label 3이 강등돼 학습 가능한 심각 샘플이 줄어 recall 하락
  • k=2/m=2 = "최근 2폴링 둘 다 심각" → 단발 스파이크는 거르고 2폴링만 지속되면 인정 → 진짜 붕괴는 대부분 살림

결과: raw label 3 319 → 284. 5시드 Label 3 recall 전 모델 +6~10pt (EE Fixed 75.2 → 85.7%), EE Dynamic Label 3 F1 86.7(프로젝트 역대 최고). 17차의 임시값 k=3/m=2에서 교체.

슬라이드 7 "라벨을 점유율로 부여" — 부정확, 수정 필요수정

확인 결과
yongsang 브랜치 확인 완료. 1학기 최종 시스템(data/real = Kaggle 6G 데이터셋)의 라벨은 4축 가중합: score = 0.35·occupancy + 0.25·latency + 0.25·loss + 0.15·rps, 문턱 35/55/75/100. 초기 traffic_simulator.py만 occupancy 단일 문턱(40/65/85)이었고 최종보고서 시스템은 아님. C1 최종보고서 서술이 맞음
슬라이드 7 "1학기 입력 4개의 문제" 문구 교체
  • "라벨을 점유율로 부여" → "라벨을 4축(RPS·점유율·손실·지연) 가중합으로 부여 (occupancy 가중치 0.35로 최대 + occupancy만 원척도라 실질적으로 점유율이 지배)"
  • leakage 논거 강화: "점유율을 입력에도 사용" → "모델 입력 4개 = 라벨 계산 4축 전부 → 모델이 정답 계산식의 재료를 다 보고 있어 사실상 정답을 읽음 (완전 leakage)"
  • 2학기 대비: "→ 라벨 축(jitter·loss·latency)을 모델 입력에서 완전히 분리"
  • 슬라이드 3도 같이: "1학기 시뮬레이터 95.7%"·"시뮬레이터 검증" → 1학기 최종 시스템은 Kaggle 6G 공개 데이터셋(시뮬레이터 아님). "공개 데이터셋(Kaggle 6G) 95.7%"로 문구 정합성

CLAUDE.md의 "채널 점유율 단일 문턱(40/65/85)" 서술은 틀린 것으로 확인 → 수정 완료. (traffic_simulator.py만 그 방식, 최종보고서 시스템은 Kaggle 가중합)
