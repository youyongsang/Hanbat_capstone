왜
슬라이드 6이 "프로브는 학습에만 쓴다"고만 함 — ① 그럼 프로브를 왜 쓰냐 ② 배포 때 어떻게 맞히냐 둘 다 Q&A 1순위인데 설명이 없음. 사실 같은 논리
슬라이드 6 "LSTM 선정 이유" 아래 또는 별도 1장

왜 victim 프로브가 필요한가: 라벨은 "실제 QoS가 깨지는가"를 나타내야 한다. 1학기처럼 점유율 문턱만 쓰면 라벨 = 점유율 규칙이라 순환논리. "QoS가 깨지는가"를 실제로 재려면 jitter·loss 실측이 필요하고, 그게 victim 프로브다. 즉 프로브는 규칙으로는 만들 수 없는 정직한 정답을 만드는 도구.

데이터 한 행 = [7개 AP feature] + [프로브·ping·점유율로 계산한 label]. 학습 시 모델에는 7개 feature만 입력하고 label을 정답으로 준다. 모델은 "feature가 이런 패턴 → label이 이거"를 반복 학습하며 그 안에 숨은 관계(예: 점유율 65% + retry 급증 + bitrate 상승 → victim QoS 붕괴 → label 3)를 내부 가중치로 압축한다. 배포 시에는 label도 프로브 값도 받지 않고 7개 feature만으로 label 확률을 출력한다 — 프로브가 하던 측정을 학습된 모델이 간접 추론으로 대체.

모델에 들어가는 것정답
학습7 featurelabel (프로브·ping·점유율로 계산) → 예측과 비교해 가중치 갱신
배포7 feature없음 — 모델이 label 직접 출력

7개 feature가 jitter/loss를 완벽히 결정하지는 않는다(occ 60~73% 애매 구간). → 모델이 배우는 건 결정론적 대응표가 아니라 확률적 매핑 → 정확도가 100%가 아닌 92%이고, 단순 lookup이 아닌 진짜 학습 문제인 이유.

단일 문턱이 맞으면: "1학기 라벨은 채널 점유율 단일 문턱(40/65/85%)으로 0~3단계를 자동 부여했다. 라벨이 사실상 점유율 규칙이라, 점유율을 입력에 포함한 LSTM은 Threshold baseline과 구조적으로 순환한다."

가중합이 맞으면: "1학기 라벨은 RPS·점유율·손실·지연을 가중 합산한 혼잡 점수로 부여했으나, 점유율 가중치가 커서 라벨이 사실상 점유율에 지배되었다. 그 점유율을 모델 입력에도 사용해 순환 구조가 되었다."

2학기 대비 문구는 동일: "→ congestion_score = max(표준 앵커) + victim 프로브로 재설계, 라벨 축은 모델 입력에서 분리"
