# 김호중 방학 4단계 가이드라인
## 실시간 혼잡 판단 데모 및 Pi 결과 분석

> 담당자: 김호중  
> 단계 목표: 실시간 입력 루프와 Pi 추론을 연결하고 최종 배포 결과를 정리  
> 완료 기준: 실시간 label/action 출력 로그와 Pi 결과 비교표 완성

---

## 1. 방학 4단계 공통 목표

4단계는 세 명 모두 **최종 분석·데모·공유 단계**다.  
새 실험을 계속 늘리기보다, 1~3단계에서 나온 결과를 한 흐름으로 묶어 정리한다.

| 담당 | 4단계 역할 |
|---|---|
| 장예나 | 데이터셋/실시간 입력/노이즈 데이터 결과 정리 |
| 김호중 | Pi 배포 결과와 실시간 혼잡 판단 데모 정리 |
| 유용상 | PC 모델 결과와 Pi 결과 연결 분석 |

---

## 2. 실시간 처리 흐름

```text
AP 지표 수집
→ 최근 10개 시점 버퍼
→ ONNX staged Early Exit 추론
→ label 0/1/2/3 출력
→ 채널 유지/전환 후보 출력
```

### 출력 예시

```text
[12:03:01] label=0 normal, action=keep, latency=1.31ms
[12:03:02] label=1 warning, action=monitor, latency=1.28ms
[12:03:03] label=2 congested, action=switch_candidate, latency=1.42ms
```

---

## 3. 정리 표

| 비교 | 포함 항목 |
|---|---|
| FP32 vs INT8 | 모델 크기, 정확도, 평균 추론 시간 |
| fixed vs dynamic | 정확도, 지연, Exit 비율 |
| CSV 평가 vs 실시간 데모 | 정량 평가와 동작 검증 분리 |
| PC vs Pi | 같은 데이터 기준 추론 시간 차이 |

---

## 4. 완료 기준 체크리스트

- [ ] 실시간 입력 10개 윈도우 수신 확인
- [ ] ONNX 추론 결과가 콘솔에 출력됨
- [ ] 채널 유지/전환 후보가 함께 출력됨
- [ ] 5분 이상 실행 로그 저장
- [ ] Pi 실측 결과표 작성
- [ ] 용상·예나에게 결과 공유

---

## 5. 주의사항

- 실시간 데모는 정량 정확도 비교보다 시스템 동작 가능성 검증에 가깝다.
- Pi 결과는 실행 환경 영향을 받으므로 반복 측정 평균과 p95를 함께 제시한다.
- 데이터 라벨링 기준은 예나 문서를 따른다.
