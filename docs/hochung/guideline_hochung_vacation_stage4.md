# 김호중 방학 4단계 가이드라인
## 실시간 혼잡 판단 데모 검증

> 담당자: 김호중  
> 목표: 실시간 수집 루프에서 들어오는 데이터를 ONNX staged Early Exit 추론에 연결  
> 완료 기준: 실시간으로 label 0/1/2/3 및 채널 유지/전환 후보가 출력됨

---

## 1. 해야 할 일 순서

```
1. 예나의 실시간 수집 루프 출력 형식 확인
2. 최근 10개 시점 윈도우를 추론 스크립트 입력으로 연결
3. ONNX staged Early Exit 추론 실행
4. 혼잡 수준 label 출력
5. 채널 유지/전환 후보 출력
6. 5분 이상 실행 로그 저장
```

---

## 2. 실시간 처리 흐름

```text
AP 지표 수집
→ 최근 10개 시점 버퍼
→ ONNX staged Early Exit 추론
→ label 0/1/2/3 출력
→ 채널 유지/전환 후보 출력
```

---

## 3. 출력 예시

```text
[12:03:01] label=0 normal, action=keep, latency=1.31ms
[12:03:02] label=1 warning, action=monitor, latency=1.28ms
[12:03:03] label=2 congested, action=switch_candidate, latency=1.42ms
```

---

## 4. 완료 기준 체크리스트

- [ ] 실시간 입력 10개 윈도우 수신 확인
- [ ] ONNX 추론 결과가 콘솔에 출력됨
- [ ] 채널 유지/전환 후보가 함께 출력됨
- [ ] 5분 이상 실행 로그 저장
- [ ] 데모용 실행 명령어 정리

---

## 5. 주의사항

- 실시간 데모는 정량 정확도 비교보다 시스템 동작 가능성 검증에 가깝다.
- 실시간 입력과 CSV 평가 결과를 혼동하지 않는다.
- 실시간 로그는 보고서/발표용 예시로 활용할 수 있도록 보관한다.
