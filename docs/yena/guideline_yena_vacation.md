# 장예나 방학 가이드라인

> 담당자: 장예나  
> 목표: 동일 테스트베드에서 실제 WiFi 트래픽 데이터를 수집하고, 실시간 혼잡 판단 입력 파이프라인을 구성  
> 완료 기준: `data/real_wifi/` 데이터셋 생성, 라벨링 기준 문서화, 실시간 수집 루프 검증

## 0. 공통 실험 원칙

방학 실측 실험은 환경 편차를 줄이기 위해 한 공간에서 고정된 장비 세트로 진행한다.

| 항목 | 기준 |
|---|---|
| 실험 장소 | 동일 공간에서 고정 수행 |
| AP | GL.iNet OpenWrt AP |
| 엣지 장비 | Raspberry Pi 4 |
| 단말 | 스마트폰 3대 + 노트북 1대 |
| 데이터 형식 | 기존 모델 입력과 동일한 CSV 형식 유지 |
| 라벨 의미 | 0 정상, 1 경고, 2 혼잡, 3 심각 |

예나의 역할은 단순히 CSV를 만드는 것에서 끝나지 않고, 실제 AP 지표가 모델 입력으로 들어갈 수 있도록 수집 구조와 라벨링 기준을 정의하는 것이다.

## 1단계. 실제 WiFi 테스트베드 구성

### 해야 할 일

```
1. GL.iNet AP 초기 설정
2. Raspberry Pi를 AP LAN 포트에 연결
3. 스마트폰 3대와 노트북 1대를 AP WiFi에 연결
4. AP와 Pi에서 지표 수집 명령 동작 확인
5. 실험 환경 사진 또는 구성도 기록
```

### 장비 구성

| 장비 | 역할 |
|---|---|
| GL.iNet AP | 실험용 WiFi AP 및 OpenWrt 지표 수집 대상 |
| Raspberry Pi 4 | 지표 수집, CSV 저장, 추론 실행 환경 |
| 스마트폰 3대 | WiFi 트래픽 생성 단말 |
| 노트북 1대 | 트래픽 생성 또는 SSH/관리용 단말 |
| LAN 케이블 | AP와 Pi 연결 |

### 완료 기준

- [ ] GL.iNet AP 관리자 페이지 접속 확인
- [ ] Pi에서 AP 또는 자체 무선 지표 명령 실행 확인
- [ ] 단말 3~4대가 실험용 WiFi에 접속됨
- [ ] 정상/경고/혼잡/심각 시나리오를 만들 수 있는지 확인

## 2단계. 실제 WiFi 데이터 수집 및 라벨링

### 수집 피처

최종 CSV는 기존 코드와 맞추기 위해 아래 컬럼을 기준으로 한다.

```csv
timestamp,rps,channel_occupancy,packet_loss,latency,label
```

| 피처 | 의미 | 수집 또는 계산 방법 |
|---|---|---|
| `timestamp` | 측정 시각 | 수집 루프 기준 시간 |
| `rps` | 요청/패킷 처리량 지표 | iperf3, ping, 패킷 카운터 기반 계산 |
| `channel_occupancy` | 채널 점유율 | `iw dev wlan0 survey dump` 또는 AP 지표 파싱 |
| `packet_loss` | 패킷 손실률 | ping/iperf3 결과 또는 인터페이스 통계 |
| `latency` | 응답 지연 | ping RTT 또는 iperf3 지연 대체 지표 |
| `label` | 혼잡 수준 | 복합 점수 또는 시나리오 기준으로 부여 |

### 라벨링 기준

실측 데이터에는 보통 정답 라벨이 없으므로, 수집 후 아래 의미에 맞게 라벨을 부여한다.

| 라벨 | 의미 | 예시 기준 |
|---:|---|---|
| 0 | 정상 | 낮은 점유율, 낮은 손실률, 낮은 지연 |
| 1 | 혼잡 경고 | 점유율 또는 지연 상승 시작 |
| 2 | 혼잡 | 점유율/손실/지연이 명확히 증가 |
| 3 | 심각 | 다중 단말 고부하, 높은 지연 또는 손실 |

라벨은 단일 피처 하나만 보지 말고, 가능하면 아래와 같은 복합 점수 기반으로 부여한다.

```text
congestion_score =
  0.45 * channel_occupancy_score
+ 0.25 * latency_score
+ 0.20 * packet_loss_score
+ 0.10 * rps_score
```

### 시나리오별 수집

| 시나리오 | 단말 구성 | 목표 라벨 |
|---|---:|---:|
| 정상 | 단말 1대 낮은 부하 | 0 |
| 혼잡 경고 | 단말 2~3대 중간 부하 | 1 |
| 혼잡 | 단말 3~4대 고부하 | 2 |
| 심각 | 단말 4대 + 대용량 전송 | 3 |

## 3단계. 실시간 입력 파이프라인 검증

### 목표

CSV 파일을 만든 뒤 끝내지 않고, AP 지표를 주기적으로 읽어서 모델 입력 형태로 변환되는지 확인한다.

```text
AP 지표 수집
→ 최근 10개 시점 버퍼 저장
→ [rps, channel_occupancy, packet_loss, latency] 윈도우 생성
→ 모델 입력 형태로 변환
→ 혼잡 수준 추론 가능 상태 확인
```

### 확인 항목

| 항목 | 확인 내용 |
|---|---|
| 수집 주기 | 1초 또는 고정 간격으로 지표가 저장되는지 확인 |
| 윈도우 구성 | 최근 10개 시점이 `(10, 4)` 형태로 구성되는지 확인 |
| 정규화 | 학습 시 사용한 피처 스케일과 맞는지 확인 |
| 추론 연결 | 호중이 제공한 Pi 추론 스크립트에 입력 가능한지 확인 |

### 완료 기준

- [ ] 실시간 수집 루프가 5분 이상 중단 없이 동작
- [ ] 수집 로그가 CSV로 저장됨
- [ ] 최근 10개 데이터 윈도우 생성 확인
- [ ] 호중의 Pi 추론 스크립트와 입력 형식 호환 확인

## 4단계. 시뮬레이터 노이즈 개선

실제 WiFi 데이터와 기존 시뮬레이터 데이터의 차이를 줄이기 위해 노이즈 추가 버전을 만든다.

```python
channel_occupancy += np.random.normal(0, 5)
packet_loss += np.random.normal(0, 1)
latency += np.random.normal(0, 10)
```
