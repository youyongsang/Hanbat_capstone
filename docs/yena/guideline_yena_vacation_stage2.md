# 장예나 방학 2단계 가이드라인
## 실제 WiFi 데이터 수집 및 데이터셋 생성

> 담당자: 장예나  
> 단계 목표: 동일 테스트베드에서 실제 WiFi 데이터를 수집하고 학습/평가용 CSV 생성  
> 완료 기준: `data/real_wifi/train.csv`, `val.csv`, `test.csv` 생성

---

## 1. 방학 2단계 공통 목표

2단계는 세 명 모두 **실측 데이터 기반 실험에 들어갈 입력을 확보하는 단계**다.  
예나는 데이터를 만들고, 호중은 Pi에서 읽을 준비를 하며, 용상은 모델 입력으로 변환되는지 확인한다.

| 담당 | 2단계 역할 |
|---|---|
| 장예나 | 실제 WiFi 데이터 수집 및 train/val/test 생성 |
| 김호중 | 수집 데이터의 Pi 배포 폴더 반영 및 실행 파일 준비 |
| 유용상 | 수집 데이터의 dataloader 호환성 검증 |

---

## 2. 해야 할 일 순서

```
1. 정상/경고/혼잡/심각 시나리오별 트래픽 생성
2. AP/Pi 지표 수집 스크립트 실행
3. 원본 raw CSV 저장
4. 최종 피처 CSV로 변환
5. label 0/1/2/3 부여
6. train/val/test 분할
```

---

## 3. 시나리오별 수집

| 시나리오 | 단말 구성 | 목표 라벨 |
|---|---:|---:|
| 정상 | 단말 1대 낮은 부하 | 0 |
| 혼잡 경고 | 단말 2~3대 중간 부하 | 1 |
| 혼잡 | 단말 3~4대 고부하 | 2 |
| 심각 | 단말 4대 + 대용량 전송 | 3 |

---

## 4. 라벨링 기준

실측 데이터에는 정답 라벨이 없으므로, 시나리오 기준과 복합 점수 기준을 함께 사용한다.

```text
congestion_score =
  0.45 * channel_occupancy_score
+ 0.25 * latency_score
+ 0.20 * packet_loss_score
+ 0.10 * rps_score
```

## 6. 주의사항

- 실측 데이터와 시뮬레이터 데이터는 반드시 구분해서 저장한다.
- CSV 형식은 1단계에서 확정한 형식을 유지한다.
- 라벨 기준은 모델 성능 해석에 직접 영향을 주므로 임의로 바꾸지 않는다.
