# 유용상 방학 4단계 가이드라인
## 노이즈/실측/배포 결과 통합 분석

> 담당자: 유용상  
> 단계 목표: 기존 시뮬레이터, 노이즈 시뮬레이터, 실측 데이터, Pi 결과를 연결해 최종 분석 정리  
> 완료 기준: PC 모델 결과와 Pi 배포 결과를 연결한 분석 문서 완성

---

## 1. 방학 4단계 공통 목표

4단계는 세 명 모두 **최종 분석·데모·공유 단계**다.  
새 실험을 계속 늘리기보다, 1~3단계에서 나온 결과를 한 흐름으로 묶어 정리한다.

| 담당 | 4단계 역할 |
|---|---|
| 장예나 | 데이터셋/실시간 입력/노이즈 데이터 결과 정리 |
| 김호중 | Pi 배포 결과와 실시간 혼잡 판단 데모 정리 |
| 유용상 | PC 모델 결과와 Pi 결과 연결 분석 |

---

## 2. 분석 대상

| 데이터/결과 | 분석 목적 |
|---|---|
| 기존 시뮬레이터 | 기준선 비교 |
| 노이즈 추가 시뮬레이터 | 동적 θ 효과 확인 |
| 실제 WiFi 데이터 | 실환경 입력 재검증 |
| 호중 Pi 결과 | 배포 환경에서 지연/Exit 분포 확인 |

---

## 3. 분석 포인트

| 항목 | 확인 내용 |
|---|---|
| 전체 정확도 | 고정 θ와 동적 θ가 정확도를 유지하는지 |
| 추론 시간 | 동적 θ 오버헤드가 줄었는지 |
| Exit1 비율 | 안정 구간에서 조기 종료가 늘어나는지 |
| Exit3 비율 | 깊은 추론 비율이 줄어드는지 |
| 급변 구간 정확도 | 혼잡 변화가 큰 구간에서 동적 θ가 유리한지 |
| PC vs Pi | 모델 경향이 배포 환경에서도 유지되는지 |

---

## 4. 전달 항목

| 항목 | 설명 |
|---|---|
| 모델 구조 변경사항 | Early Exit LSTM 코드 변경 여부 |
| 최종 threshold 설정 | 고정 θ, 동적 θ 초기값, spike 기준 |
| 실측 데이터 PC 결과 | 정확도, 추론 시간, Exit 비율 |
| 호중 Pi 결과 해석 | FP32/INT8, fixed/dynamic 비교 |

## 6. 주의사항

- 실측 데이터 결과와 시뮬레이터 결과는 반드시 분리해서 표기한다.
- Pi 실측 성능은 호중 결과를 기준으로 인용한다.
- 용상 브랜치에서는 PC 기준 모델 재검증에 집중한다.
