## 2. 고정 θ vs 동적 θ 최종 분석

3단계 실험 결과를 바탕으로 최종 분석을 정리한다.

### 분석 프레임

| 항목 | 고정 θ | 동적 θ | 해석 |
|---|---|---|---|
| 전체 정확도 | | | |
| 평균 추론 시간 | | | |
| Exit 1 종료율 | | | |
| 긴급 증산 정확도 | | | |
| 안정 구간 Exit 1 종료율 | | | |

### 핵심 분석 포인트

**동적 θ가 오버헤드로 인해 실측 시간이 더 긴 이유:**

```
동적 θ 매 타임스텝 추가 연산:
최근 N 타임스텝 슬라이싱 → std 계산 → 조건 분기 → θ 재설정

이 연산 비용 > Exit 1 종료율 향상으로 절약한 시간
→ 전체 실측 시간 오히려 증가
```

**그럼에도 동적 θ의 의미:**
- Exit 1 종료율이 고정 θ 대비 일관되게 높음
- 안정 구간에서 불필요한 깊은 추론을 줄이는 경향 확인
- 계산 경량화가 이루어지면 이득이 오버헤드를 초과할 수 있음

## 3. 동적 θ 한계 원인 분석

### 원인 1 — 연산 오버헤드

```
현재 구현:
np.std(recent_window)  ← N개 값의 분산 계산 + 제곱근
→ 개선 방향: max-min 범위로 대체, 주기적 업데이트
```

### 원인 2 — 시뮬레이터 데이터 특성

```
시뮬레이터 데이터의 패턴이 명확함
→ 고정 θ로도 충분히 분류 가능
→ 동적 θ의 정확도 향상 효과 미미

실제 환경에서는 노이즈, 불규칙한 변동이 있어
→ 동적 θ의 강건성이 더 두드러질 것으로 예상
```

### 원인 3 — 파라미터 최적화 한계

```
HIGH_VARIANCE, MID_VARIANCE 등의 기준값이
이 데이터에 완전히 최적화되지 않았을 수 있음
```

### 보고서 작성 시 주의사항

> "동적 threshold는 규칙 기반 변동률 계산으로 구현하였으며, Exit 1 종료율이 고정 threshold 대비 일관되게 높게 나타났다. 그러나 변동률 계산 오버헤드로 인해 실측 추론 시간은 고정 threshold 대비 증가하였다. 이는 현재 std 기반 계산의 연산 비용이 Exit 1 종료율 향상으로 얻는 시간 절약을 초과하기 때문으로 분석된다. 향후 max-min 범위 기반 경량 계산 또는 주기적 업데이트 방식으로 오버헤드를 줄이는 것이 개선 방향이다."
