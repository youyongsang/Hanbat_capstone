혼잡 판단 LSTM의 입력과 출력

자원할당해조 · 2026-10-29 · 대상 모델: 현행 배포 Early Exit LSTM (2.4GHz, 24세션 학습) · 코드 정본 project/utils/ap_features.py, project/models/early_exit_lstm.py

입력 — 공유기(AP)가 약 1초마다 스스로 잴 수 있는 무선 채널 상태 값 7개를, 최근 12번(약 12초) 모은 표 한 장. 크기 [12 × 7].

출력 — 그 12초의 마지막 시점에 이 채널의 혼잡 등급이 무엇인지: 0 정상 1 경고 2 혼잡 3 심각 네 등급의 확률과, 그중 가장 높은 등급 하나.

학습 — 같은 시점에 별도 측정 장비로 잰 "실제 통신 품질(지연·지터·손실)"과 채널 점유율을 국제 표준 문턱으로 채점해 정답 등급을 만들고, 모델이 그 품질 측정값은 보지 못한 채 AP 값 7개만으로 정답 등급을 맞히도록 학습한다.

즉 이 모델이 푸는 문제는 "AP가 이미 가지고 있는 채널 정보만으로, 이 채널을 쓰는 단말들의 통신 품질이 지금 어느 정도 망가졌는지를 추정하라"이다. 실제 품질 측정(지연·손실)은 협조 단말과 상시 시험 트래픽이 있어야 해서 실제 운용 환경에는 없다는 점이 출발점이다.

2. 입력 (X) — 무엇을 받는가

2.1 값 7개 (1회 측정 = 1행)

모두 AP 운영체제(OpenWrt)의 표준 명령 iw station dump, iw survey dump로 AP 혼자 얻을 수 있는 값이다. 단말에 프로그램을 깔거나 추가 장비를 둘 필요가 없다.

2.2 시간 축 — 왜 12회를 묶나

한 번의 측정값만 보면 "지금 점유율 70%"는 알아도 "올라가는 중인지, 잠깐 튄 것인지"는 모른다. 그래서 최근 12회(약 12초)를 시간 순서대로 쌓은 12행 × 7열 표를 한 개의 입력으로 쓴다. LSTM은 이 12행을 위에서부터 순서대로 읽으며 추세를 기억한다. 12는 10·12·13·14·15·20을 여러 시드로 비교해 가장 좋았던 값이다.

새 측정이 하나 들어올 때마다 가장 오래된 행을 버리고 새 행을 붙이므로(슬라이딩 윈도우), 실시간으로는 약 1초마다 한 번씩 판단한다.

2.3 정규화

단위가 제각각(Mbps, %, dBm)이라 학습 데이터의 최솟값·최댓값으로 각 열을 0~1로 바꾼다: (값 − 최소) / (최대 − 최소). 이 최소·최대(scaler_params.json)는 학습 때 한 번 정하고, 평가·실시간 추론에도 같은 값을 그대로 쓴다. 예: 점유율은 8.62~93.1%, 신호세기는 −57~0 dBm 범위를 0~1로 옮긴다.

2.5 일부러 넣지 않은 값

지연(latency)·지터(jitter)·패킷 손실(loss)은 입력에 없다. 이 셋은 정답 등급을 만드는 재료(3장)이기 때문에 입력에 넣으면 모델이 답을 보고 푸는 셈이 된다. 또 실제 운용 환경에서는 이 값을 재려면 협조 단말과 상시 시험 트래픽이 필요해 AP 혼자서는 얻을 수 없다. (1학기 모델은 지연·손실을 입력과 정답에 동시에 써서 이 문제가 있었고, 2학기에 바로잡았다.)

3. 정답 (y) — 무엇을 학습하는가

데이터를 모을 때만, AP와 별도로 "피해자 측정 스트림"을 흘린다: 폰 한 대가 300kbps짜리 작은 음성통화 크기 UDP 트래픽을 계속 보내고, 그 트래픽이 실제로 겪는 지터·손실과 ping 지연을 잰다. "이 혼잡 속에서 통화 한 통이 얼마나 깨지는가"를 직접 잰 값이다.

정답 등급 만드는 법 (1초 측정 1행마다)

  1. 네 축(채널 점유율, 지터, 손실, 지연)을 각각 표준 문턱에 맞춰 0~1 점수로 바꾼다. 심각 문턱 예: 지터 50ms(ITU-T Y.1541), 편도 지연 150ms(ITU-T G.114), 손실 5%(Cisco QoS 가이드), 점유율 75%(Aruba WLAN 가이드).
  2. 네 점수 중 가장 나쁜 값을 고른다 → 0.25 미만 정상 / 0.50 미만 경고 / 0.75 미만 혼잡 / 0.75 이상 심각.
  3. 품질 축이 단 1초만 심각을 넘은 순간 튐은 심각으로 치지 않는다 (2초 연속일 때만 심각).

상세 근거: docs/yongsang/congestion_label_redesign.html

창 하나의 정답 = 그 12초 창의 마지막(12번째) 시점의 등급. 즉 모델은 "과거 12초를 보고 지금 이 순간의 등급"을 맞힌다(미래 예측이 아니다).

3.1 학습 방법

  • 데이터: 실제 공유기(GL.iNet Opal)에서 직접 수집한 24개 세션(부하 방향·세기·배치를 바꿔 가며), 세션 단위로 나눠 학습 13,858창 / 검증 5,575창.
  • 손실 함수: 세 출구가 모두 정답을 맞히도록 각 출구의 교차 엔트로피를 가중합 — 0.3 × 출구1 + 0.3 × 출구2 + 0.4 × 출구3. 그래서 얕은 출구도 혼자서 등급을 낼 수 있게 훈련된다.
  • 설정: Adam, 학습률 0.001, 배치 32, 50에폭, 드롭아웃 0.2. 클래스 수가 고르지 않아 검증 균형 정확도(등급별 재현율 평균)가 가장 높은 에폭을 저장.
  • 무작위 시드 5개로 학습해 비교했고, 배포 모델은 검증 균형 정확도가 가장 높은 시드를 골랐다.

5. 출력 (ŷ) — 무엇을 내놓는가

5.1 출력 3가지

출력모양뜻
등급 확률숫자 4개, 합 1정상·경고·혼잡·심각 각각일 확률 (softmax)
최종 등급0, 1, 2, 3 중 하나확률이 가장 큰 등급
종료 출구1, 2, 3 중 하나몇 층까지 계산하고 끝냈는가 (계산량·지연에 해당)

Raspberry Pi에 올린 ONNX 파일의 실제 출력 이름은 logits(크기 [1,4], softmax 전 점수)와 exit_point(1~3).

5.2 어느 출구에서 멈추나 (Early Exit)

출구 1의 확률 분포가 한쪽으로 확실하게 쏠려 있으면 2·3층을 계산하지 않고 바로 답을 낸다. 쏠림 정도는 엔트로피로 잰다 — 한 등급이 100%면 0, 네 등급이 25%씩이면 최대 1.386.

  • 출구 1 엔트로피 < 0.3 → 출구 1의 답으로 끝
  • 아니면 2층 계산, 출구 2 엔트로피 < 0.6 → 출구 2의 답으로 끝
  • 아니면 3층까지 계산해 출구 3의 답

고정(Fixed)은 위 문턱을 그대로 쓰고, 동적(Dynamic)은 직전 1초 사이 점유율이 크게 변하지 않았으면 문턱을 1.25배로 느슨하게 해 더 일찍 끝낸다(상황이 안정적이면 얕게, 급변하면 깊게). 둘은 같은 학습 모델에 종료 규칙만 다르게 적용한 것이다.

검증 데이터 5,575창 기준(고정 규칙) 출구 1에서 24%, 출구 2에서 42%, 출구 3까지 간 것이 34%. Raspberry Pi INT8 기준 평균 추론 시간 약 0.6~0.7ms로, 3층을 항상 다 쓰는 일반 LSTM(약 0.86ms)보다 21~32% 빠르다.

5.4 출력을 어디에 쓰나 (모델 밖 후처리)

모델 출력은 1초마다 나오는 "현재 등급"이다. 채널 전환 같은 실제 조치는 한 번의 출력이 아니라 연속된 출력으로 판단한다.

  • 채널 전환 판단: 최근 3번 중 2번 이상 심각이면 전환 후보, 전환 뒤 30초는 다시 전환하지 않음.
  • 화면 표시: 같은 등급이 3번 연속 나와야 표시 등급을 바꿔 깜빡임을 막음.

6. 한 문장으로 다시

"공유기가 1초마다 스스로 아는 채널 상태 7가지의 최근 12초 흐름(12×7)을 입력으로 받아, 별도 측정으로 채점한 실제 통신 품질 기준의 혼잡 등급(정상·경고·혼잡·심각)을 출력하도록 학습한 3층 LSTM이며, 판단이 쉬우면 1·2층에서 일찍 답을 내 추론 시간을 줄인다."

7. 자주 나올 질문

Q. 미래를 예측하나? 아니다. 마지막 시점의 현재 등급을 분류한다. 과거 12초는 현재를 더 정확히 판단하기 위한 맥락이다.

Q. 단말 한 대의 상태인가, 채널 전체인가? 채널 전체다. 입력 값은 모든 단말을 합치거나 평균낸 값이고, 출력은 "이 채널을 쓰는 단말들의 품질이 얼마나 깨졌나"이다.

Q. 점유율만 보면 되지 않나? 점유율이 75%를 넘는 심각은 점유율 문턱 규칙으로도 맞힌다. 모델이 따로 맡는 몫은 점유율은 그보다 낮은데 실제 품질이 무너진 경우(예시 C)와 심각 진입을 조금 일찍 알아차리는 것이다. 이 몫은 일부만 회수되며, 공유기가 무엇을 측정해 주느냐에 크게 좌우된다(예: AP가 자기 송신을 점유율에 넣지 않는 다운링크 혼잡은 입력에 흔적이 없어 못 잡는다).

Q. 혼잡의 원인(약한 단말 vs 채널 포화)도 알려 주나? 아니다. 출력은 등급뿐이다. 원인 구분은 별도 규칙 단계에서 한다.
