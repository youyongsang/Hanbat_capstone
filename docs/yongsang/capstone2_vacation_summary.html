02라벨 재설계 — 순환논리를 끊다

occupancy 단일 문턱으로 라벨을 만들면 "occupancy 문턱 vs 모델" 비교가 순환이 된다. 라벨의 축을 바꿨다.

2026-08-27
가중합 → max(표준 앵커) + victim 프로브

congestion_score = max(occupancy, jitter, loss, latency). 각 축을 국제 표준 문턱(Cisco WLAN 설계 가이드, ITU-T Y.1541 / G.114)에 piecewise-linear 매핑. max라 가중치 논쟁이 원천 봉쇄된다 — "label 3 = 최소 한 축이 표준 심각 문턱 돌파".

jitter·loss는 부하와 별개로 흘리는 경량 UDP victim 스트림이 그 스트림에서 직접 겪은 값 ("이 혼잡 속에서 VoIP 한 통이 얼마나 깨지나"). 채널이 바쁜데 victim 경로가 완전히 죽으면 그 축을 1.0으로 본다(실패 = max).

2026-08-27
9 → 6 feature: 정답을 입력에서 뺐다

latency_ms·jitter_ms를 모델 입력에서 제거(−2). 이들은 라벨을 만드는 축이자 배포 시점엔 없는 측정(협조 싱크 필요). 모델에 주면 정답 leakage — 모델은 AP-side 텔레메트리만 보고 victim QoS가 깨지는지 예측해야 한다. 이게 이 프로젝트가 규칙으로 못 하는 진짜 예측 문제인 이유.

같은 재설계에서 tx_retries·tx_failed 2개를 tx_retry_ratio 하나로 통합(−1). 9 − 2 − 1 = 6. (이후 8/29에 sta_tx_bitrate_mean 추가 → 7.)

2026-08-27
유선 관리채널 + 지속 SSH poller

루프마다 SSH 핸드셰이크를 반복하던 것이 혼잡할수록 자기참조적으로 느려졌다(폴링 지연 최대 156초). 지속 세션 하나로 스트리밍하고, 수집기를 라즈베리 파이(유선)로 옮겨 관리 트래픽을 무선 채널에서 분리.

047-feature 승격 · 시드 고정 · 목표 재확인

2026-08-29
sta_tx_bitrate_mean을 7번째 입력으로

다른 6개 feature 평균이 label 2/3 사이에 완전히 동일해지는 occ 60~72% 구간에서, station tx bitrate가 두 라벨을 Cohen's d=0.52로 가른다. 5개 랜덤 시드로 검증 — exit-loss 가중치와 무관하게 7-feature가 항상 이겼다(+5~11pt).

2026-08-29
학습 파이프라인에 --seed 추가

그때까지 시드 고정이 아예 없었다. 같은 설정을 시드만 바꿔 돌리니 test 정확도 91.3% → 80.0%로 요동. 이후 모든 하이퍼파라미터 A/B는 다중 시드로만.

2026-08-29
발표자료로 목표를 다시 봤다

정량 목표는 정확도 95%와 지연 <1ms 둘뿐. SDN 비교는 원래 목표가 아니고, 핵심 기여는 "간섭 감지에 Early Exit LSTM 구조를 최초 적용". confusion matrix 분해 결과 label 2 오답이 label 3보다 많아 — 95% 목표엔 label 2 개선이 더 효율적.

05class-weight-power 재검증 · 전체 승격

2026-08-23에 굳힌 기본값 하나가, 두 번의 데이터 변화를 견디고도 재검증 안 돼 정확도를 흘리고 있었다.

2026-08-30
"절벽"은 4-feature 시절 것이었다

power=1.0은 train label-3이 23개뿐이던 옛 데이터에서, "power를 낮추면 label 3 recall이 0%로 떨어지는 절벽" 때문에 정한 값. 지금은 train label-3이 141개 — 절벽이 사라졌다. 재스윕(0.0~1.0, 3시드씩): power=0.0(가중치 없음)이 정확도(91.3% vs 87.0%)와 label 3 F1(69.8% vs 63.2%)을 동시에, 트레이드오프 없이 이겼다.

2026-08-30
전체 승격 + 5시드 특성화

세 모델 재학습(Baseline·SDN 3시드, EE 5시드), val balanced acc 최고를 배포. Baseline 배포 체크포인트를 seed0 → seed3으로 교체(seed0의 높은 test 정확도는 운 좋은 draw였다).

2026-08-30
SDN을 논문대로 다시 구현

기존 "SDN-style"은 우리 모델과 백본·헤드가 100% 같아 비교 모델로 성립하지 않았다. Kaya et al.(Shallow-Deep Networks, ICML 2019) 공식 코드대로 — pooling internal classifier, 커리큘럼 램프 depth-weighted loss, val 캘리브레이션 confidence threshold. base 백본만 공유(통제 변수).

2026-08-30

07목표1 재공략 — window 스윕 + 데이터 수집 (2026-09-01)

window/lr/batch/EMA 스윕 → window 12만 이득. 이어서 소패킷 부하로 데이터를 더 모았다.

되돌린 결정 — 그리고 왜

정직한 기록. 매번 "성급한 결론"이 재확인 질문이나 다중 시드 검증으로 바로잡혔다.

Reversed

  • ✗SDN 스타일 exit-loss 가중치 승격 → 단일 실행 비교였고 시드만 바꾸니 F1이 66.7%→51.1%로 요동. 다중 시드에서 균등 가중치와 차이가 표준편차 이하 → 철회. (이 사건이 --seed 추가의 계기.)
  • ✗occupancy 라벨링 스무딩(window 5·3) → 경계 노이즈는 절반 줄었지만 같은 스무딩 값이 다른 앵커 경계에도 쓰여 새 오답 발생. 순효과 없음(두더지 잡기) → 폐기.
  • ✗모델 입력 EMA 스무딩(α 0.3/0.5/0.7, 2026-09-01) → 다중 시드에서 순효과 없음. 스무딩 방향 2연속 폐기 — 대신 window 10→12가 같은 경계 노이즈에 유효했다.
  • ✗class-weight-power=1.0의 "절벽" 가정 → 4-feature·23샘플 시절 근거. 데이터가 6배 늘며 절벽 소멸 — 재검증 안 해 계속 손해. → 0.0.
  • ✗1차 데이터 재사용 → ap_cleaned_strict가 실측이 아님을 확인, 재라벨링 포기하고 2차 라인으로.
