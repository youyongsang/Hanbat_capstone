MT6000 설정 가이드

MT6000이 도착한 날 보면서 따라 하는 절차다. 목표는 하나: 2.4GHz에서 AP 자신의 송신 시간(tx duration, channel transmit time)이 나오는지 확인하고, 나오면 Opal과 같은 실험 환경으로 맞춰 수집을 시작하는 것. 기본 펌웨어에서 값이 나오면 OpenWrt 설치는 건너뛴다.

1단계기본 펌웨어 그대로 점검 (약 30분)
2단계값이 안 나올 때만, 한 대에 순정 OpenWrt 25.12 설치 (약 1시간)
3단계실험 환경 맞추기 → 다운링크 step으로 진행 여부 판단
factory 이미지 금지반드시 sysupgrade 이미지 (공식 페이지: factory는 벽돌 위험)

왜 이 기기인가 (근거)

  • Opal(Siflower siwifi 드라이버)의 점유율은 AP 자신의 송신을 빼고 센다. 그래서 다운링크 혼잡과 노트북 방향의 점유율 미달 심각(줄 적체)이 안 보였다(final_model_24sess.html 2-1·5-1절).
  • OpenWrt 포럼 스레드 173524, 사용자 질문 #3112에 대한 hnyman(OpenWrt Guru)의 답글 #3114: GL-MT6000 실기기·순정 OpenWrt 스냅샷(r36162)에서 iw station dump의 tx duration·rx duration·airtime weight, iw survey dump의 channel busy/receive/BSS receive/transmit time이 실제 값으로 출력됐다. 사용 채널에서 busy ≈ receive + transmit → MT6000의 busy는 AP 송신을 포함한다.
  • OpenWrt 공식 하드웨어 페이지(openwrt.org/toh/gl.inet/gl-mt6000): 공식 지원 기기, MediaTek Filogic 830(4코어 2.0GHz), 무선 드라이버 MT76(mt7915e). 설치는 sysupgrade 이미지, U-Boot 복구 화면은 어떤 펌웨어 상태에서도 동작.
  • 아직 확인 안 된 것: 포럼 출력은 5GHz였다(2.4GHz 미확인). GL.iNet 기본 펌웨어에서도 나오는지 미확인. #3112에서 물은 "AQL/airtime fairness·WED 오프로드와의 관계"는 답이 없었다.

도착 전준비

  • Opal 설정 백업 (Opal이 켜져 있을 때): 고정 IP 목록과 무선 설정을 파일로 남긴다. 
    ssh root@192.168.8.1 "uci show dhcp | grep -E 'host|mac|ip|name'; uci show wireless" > opal_config_backup.txt
  • 현재 Opal 2.4GHz: 채널 1, 40MHz(h18 시점 스냅샷). MT6000도 같은 채널로 맞추면 비교가 쉽다.
  • OpenWrt 이미지 미리 받기(2단계 대비): Firmware Selector에서 GL-MT6000 → 25.12 안정판 sysupgrade 이미지와 sha256 값.
  • 노트북 공개키: ~/.ssh/id_rsa_ap.pub(지금 AP 접속용 키). Pi도 AP에 SSH로 붙으므로 Pi의 공개키도 준비: ssh capstone@192.168.8.109 "cat ~/.ssh/id_*.pub"
  • 수집기는 이미 준비됨(collect_metrics.py에 airtime 컬럼 5개, AP_IP·AP_INTERFACE 환경변수). 첫날 점검 스크립트 project/scripts/mt6000_day1_check.sh. Pi 번들에는 아직 안 올림 → 수집 전에 Pi로 복사.

1단계기본 펌웨어로 점검

  1. Opal을 끈다. 둘 다 192.168.8.1이라 동시에 켜면 주소가 충돌한다.
  2. 동봉 이더넷 케이블로 노트북과 MT6000 LAN 포트를 연결하고 전원을 켠다.
  3. 브라우저로 192.168.8.1 → 언어 선택 → 관리자 비밀번호 설정(직접 입력). 이 비밀번호가 SSH root 비밀번호가 된다.
  4. 관리 화면의 시스템 → 업그레이드에서 GL.iNet 펌웨어를 최신으로 올린다(상품 설명이 권하는 업데이트).
  5. 2.4GHz Wi-Fi 켜기. Wi-Fi 이름·비밀번호는 바닥 라벨 참고(없으면 goodlife 시도), 채널 1. 폰 한 대를 붙인다.
  6. 노트북에서 SSH가 바뀐 기기를 거부하지 않게 예전 Opal 키를 지운다: 
    ssh-keygen -R 192.168.8.1
  7. 점검 스크립트 실행: 
    bash project/scripts/mt6000_day1_check.sh 192.168.8.1
    확인 항목: ① 펌웨어·드라이버 ② 2.4GHz 인터페이스 이름 ③ tx duration·rx duration ④ survey의 transmit·receive·BSS receive ⑤ busy ≈ receive + transmit.

tx duration·transmit time 나옴2단계 건너뛰고 3단계로
안 나옴2단계(순정 OpenWrt)를 한 대에만

2단계순정 OpenWrt 설치 (필요할 때만, 한 대만)

  1. 받아 둔 sysupgrade 이미지의 sha256을 확인한다. factory 이미지는 쓰지 않는다.
  2. GL.iNet 관리 화면 → 업그레이드 → 로컬 업그레이드 → 파일 선택 → "설정 유지(Keep Settings)" 해제 → 업로드.
  3. 3~5분 기다린다. 이 동안 전원을 끄지 않는다.
  4. 유선 연결 상태로 192.168.1.1 접속 → root 비밀번호 설정(직접 입력). 순정 OpenWrt는 Wi-Fi가 꺼진 채로 시작한다.
  5. 3단계의 설정 명령을 실행한 뒤 1단계 7번 점검을 다시 한다.

두 대 중 한 대는 GL.iNet 기본 펌웨어로 남겨 둔다. 설치가 꼬여도 실험을 이어갈 수 있고, 두 펌웨어의 출력을 비교할 수도 있다.

3단계실험 환경 맞추기

목표: Opal 때와 같은 주소·SSID 구조로 맞춰 러너와 수집기를 거의 그대로 쓴다. 아래는 순정 OpenWrt 기준 명령이다(GL.iNet 펌웨어는 관리 화면에서 같은 항목을 설정). 실행 전에 uci show wireless | grep band로 어느 radio가 2.4GHz인지 확인한다(보통 radio0).

# 1) LAN 주소를 Opal과 같게 (러너·수집기·고정 IP를 그대로 쓰기 위해). 적용 후 노트북 재접속은 192.168.8.1
uci set network.lan.ipaddr='192.168.8.1'

# 2) 2.4GHz 켜기·채널·국가 코드 (해외 판매자 제품이라 국가 코드 확인)
uci set wireless.radio0.disabled='0'
uci set wireless.radio0.channel='1'
uci set wireless.radio0.htmode='HE40'
uci set wireless.radio0.country='KR'
uci set wireless.default_radio0.ssid='<새 SSID>'
uci set wireless.default_radio0.encryption='psk2'
uci set wireless.default_radio0.key='<비밀번호, 직접 입력>'

# 3) 고정 IP (opal_config_backup.txt의 MAC 사용) — 노트북 .226 · s21 .191 · s26 .103 · Pi .109
uci add dhcp host; uci set dhcp.@host[-1].name='laptop'; uci set dhcp.@host[-1].mac='14:85:7f:9b:2f:80'; uci set dhcp.@host[-1].ip='192.168.8.226'
#   (s21·s26·Pi도 같은 방식으로 추가)

uci commit; reload_config
# 4) SSH 키 등록 (노트북·Pi 공개키) — 이후 수집기가 비밀번호 없이 접속
cat ~/.ssh/id_rsa_ap.pub | ssh root@192.168.8.1 "cat >> /etc/dropbear/authorized_keys"
ssh capstone@192.168.8.109 "cat ~/.ssh/id_*.pub" | ssh root@192.168.8.1 "cat >> /etc/dropbear/authorized_keys"
ssh capstone@192.168.8.109 "ssh-keygen -R 192.168.8.1"   # Pi도 예전 Opal 호스트 키 삭제
  • SSID가 바뀌면 러너의 EXPECT_SSID(지금 GL-SFT1200-a08)와 폰·노트북 Wi-Fi 연결을 바꿔야 한다. 폰 MAC은 랜덤이라 Wi-Fi를 "잊고" 다시 붙으면 MAC이 바뀌어 고정 IP가 깨질 수 있다.
  • 수집기 실행: AP_IP=192.168.8.1 AP_INTERFACE=<2.4GHz 인터페이스> python3 collect_metrics.py <시나리오>. 순정 OpenWrt의 인터페이스 이름은 보통 phy0-ap0(점검 스크립트가 알려 줌). 러너는 IFACE 값을 바꾼다.
  • Pi 번들 갱신: scp project/deploy/raspberry_pi_ap_v2/collect_metrics.py capstone@192.168.8.109:ap_pi_v2/

판단진행할지 정하는 시험 (다운링크 step 한 번)

폰당 10→40M 다운링크(WIRED_MODE=down, h9와 같은 부하)를 한 번 돌리며 channel_tx_time_percent, channel_occupancy_percent, sta_tx_airtime_pct를 본다.

관찰판단
transmit %·busy %가 부하를 따라 오른다본 수집 시작 — 다운링크 혼잡이 MT6000에서는 보인다
Opal처럼 그대로이거나 내려간다MT6000 계측 중단 — Opal 결과로 마무리, MT6000은 멀티 AP 실험·향후 과제로

참고: Opal에서 h9 다운링크 step은 점유율이 20 → 10%로 오히려 내려갔다.

수집 전에 정할 것

  • 라벨의 점유율 축: MT6000의 busy는 AP 송신을 포함해 Opal과 의미가 다르다. 같은 75% 앵커를 쓰면 다운링크도 점유율로 심각이 붙는다. 라벨 기준을 먼저 정하고, MT6000 데이터는 Opal과 섞지 않고 따로 학습한다.
  • 세션 구성(10/14~17): 노트북 방향·업링크·다운링크·혼합 각 2~3세션 + 폰 1대·근접·소패킷 고처리량 세션(g6 오탐 대비, 거리 바꿔 2~3개). 폰 대수·거리를 섞는다.
  • 멀리 두는 세션은 Opal 크래시 경험(폰 신호 비대칭)을 참고하되, MT6000은 4코어라 고부하를 더 견딜 것으로 기대.

문제가 생기면: U-Boot 복구

  1. 전원을 끄고 리셋 버튼을 누른 채 전원을 켠다. LED가 바뀔 때까지 몇 초 누른다.
  2. 노트북 유선 포트 IP를 192.168.1.2 / 255.255.255.0으로 고정한다.
  3. 브라우저로 192.168.1.1 → 복구 화면에서 sysupgrade 이미지(OpenWrt 또는 GL.iNet)를 올린다.
  4. GL.iNet 기본 펌웨어로 돌아가려면 GL.iNet의 sysupgrade 이미지를 "설정 유지 없이" 올린다.
